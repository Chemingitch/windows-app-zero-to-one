# 仿作模式 · 照着现有软件做一个

当用户说"做一个像 XX 的软件 / 仿 XX / 照着 XX 做一个"时，本技能进入**仿作模式**。
核心动作：**先追问功能，再动手**。仿作的目标是"做出同等体验的最小实现"，不是逐像素复刻。

## 触发信号

- "做一个像 <软件名> 的"
- "仿 <软件名>"
- "照着 <软件名> 做一个"
- "XX 挺好用，给我来一个"

只要用户拿一个**已存在的软件**当参照，就走这一节，不要直接进入选型。

## 必须一次性追问的功能点

用 AskUserQuestion 或一轮连续的提问，把功能拆成三档。不要挤牙膏式追问。

| # | 要问的 | 为什么 |
|---|---|---|
| 1 | 参考的是哪个软件？你**最在意它的哪一点**？ | 抓住"灵魂"，避免被表面 UI 带偏 |
| 2 | **必做**的核心功能（逐条列出来） | 圈定 MVP，第一版只做这些 |
| 3 | 可以**砍掉 / 简化**的功能 | 先做最小可用，后续再迭代 |
| 4 | 目标形态：窗口 / 命令行 / 常驻后台 | 复用 SKILL.md 阶段 0 的形态询问 |
| 5 | 有没有界面参考（截图 / 描述 / 配色） | 减少来回确认，直接对齐观感 |
| 6 | 数据从哪来？要不要**兼容原软件的文件格式**？ | 决定本地存储 vs 联网、是否要解析旧格式 |
| 7 | 给谁用、要不要联网 | 影响签名策略与杀软误报 |

## 产出格式

一份不超过 15 行的清单，分三档：

```
定位：做一个像 <软件> 的 <一句话>
必做：
  - 功能 A
  - 功能 B
可选（后续迭代）：
  - 功能 C
不做（第一版砍掉）：
  - 功能 D（原软件有，但本次不需要）
形态：窗口程序 / 命令行工具
数据：本地单文件 / 联网 API
```

拿到这份清单后，再进入 SKILL.md 阶段 1 选型（Go / .NET / Python）。

## 示例 1：做一个像"记事本"的程序

追问后得到：

```
定位：轻量纯文本编辑器
必做：
  - 打开 / 编辑 / 保存 .txt
  - 新建窗口
  - 字号缩放
可选：
  - 查找替换
  - 自动换行开关
不做：
  - 语法高亮（VS Code 的事）
  - 云同步
形态：窗口程序（WinForms）
数据：本地文件
```

→ 选 C# + dotnet CLI（原生 GUI，不用 VS），直接 `dotnet new winforms`。

## 示例 2：做一个像"Everything"的本地搜索

```
定位：极速本地文件名搜索
必做：
  - 输入即过滤文件名
  - 结果显示路径 + 双击打开
可选：
  - 正则匹配
  - 按修改时间排序
不做：
  - 全文内容索引（太重）
  - 网络搜索
形态：窗口程序
数据：只读本地文件系统（不写任何东西）
```

→ 选 C# 或 Go；强调"只读、不写盘"，降低杀软误报。

## 原则

- **仿作 ≠ 复刻**：做出同等体验的最小实现，先交付能用的，再迭代。
- **功能 > 界面**：先定必做功能，界面只是载体。
- **敢砍**：用户说"像 XX"时往往只想要 XX 的某一个点，帮他把其它点砍掉。
- **格式兼容要问**：很多仿作掉坑在"要不要读原软件的文件"，这一条一定要问。
